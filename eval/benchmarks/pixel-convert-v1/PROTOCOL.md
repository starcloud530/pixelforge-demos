# 协议 Protocol

v1 比较的是同一张源图、同一个目标尺寸、同一个不透明色上限下的转换结果。方法之间只允许换引擎或换外部实现，不允许换尺寸、换色数上限、换展示倍率。

数字以 [protocol.json](protocol.json) 为准。本文与它对不上时，以校验脚本读到的 JSON 为准，并应改文档。

## 一次比较

每一行是：

`固件 × {64×64, 128×128} × 方法`

v1 的方法只有 `center-sample`。命令固定为：

```bash
pixelforge convert \
  --file <源 PNG> \
  --output <新工程> \
  --width <64 或 128> \
  --height <64 或 128> \
  --engine center-sample \
  --palette-strategy limit \
  --max-colors 16
```

`--output` 在文件已存在时会拒绝写入。重跑前删掉目标工程，或换一个空路径。不要改用 `--palette source` 或省略策略来「让这张图更好看」。省略策略时新工程走的是另一套封顶，而且没有 `paletteReport`，不能和本表混在一起。

源图每边不超过 4096。目标边长用上面两个尺寸，不按图另选。

## 对照栏

| 方法 id | 角色 | v1 |
| --- | --- | --- |
| `center-sample` | 基线：目标格中心覆盖到的源像素，再映射进调色板 | 已记录 |
| `traditional` | 较好的传统流程。以后可以是其它内置引擎，或仓外的量化流程 | 不跑 |
| `service` | 现成外部服务 | 不跑，不接付费 API |
| `model` | 自研转换模型 | 不跑，不在本轮训练 |

以后加入方法时，沿用同一固件、同一尺寸、同一色数上限、同一展示。新方法单独一个 `records/v1/<method>/`，不要改写中心采样那一版的哈希。

## 展示与盲评

给人看的图：

1. 用索引色画到目标尺寸。
2. 最近邻放大 4 倍。放大只重复格子，不插值。
3. 索引 0 铺成 RGB `128,128,128`。这个灰色只出现在看图上，不写回工程。
4. 两张图并排，尺寸相同，顺序随机。

票的空表是 [templates/blind-ballot.json](templates/blind-ballot.json)。评审只看见标签 A / B。方法名写在 [templates/blind-seal.json](templates/blind-seal.json)，评审看不到这份文件。

偏好只允许 `A`、`B`、`tie`。平局是有效结果，不算弃权，也不算两边都赢。一次只比同一固件、同一目标尺寸的两个方法。不把 64 和 128 放在同一张票里，也不把不同角色放在同一张票里。

没有票的时候，记录里的 `blind_preference` 保持 `null`，状态是 `pending_human`。不要用自动探针代替偏好。

## 人工特征保留

每张固件在 [manifest.json](manifest.json) 里有 `human_checklist`。评审对着铺好底的 4 倍图，按清单逐条判断「保留 / 未保留」。一张图的人工特征保留率是保留条数除以清单条数。

自动探针的通过率写在 `feature_retention_auto`。它不是人工特征保留率，不能抄进 `feature_retention_human`。

## 严重缺陷

人工代码只有这五个，多选：

| 代码 | 含义 |
| --- | --- |
| S1 | 剪影碎了，或画面上多出一块不像源图的色块 |
| S2 | 清单里的细装备线消失，或肿成不再像线的一块 |
| S3 | 透明区域被填上颜色，或边缘拖出色晕 |
| S4 | 源图里分开的颜色身份被换成了另一种身份。16 色预算内不得不合并邻近色带，本身不是 S4 |
| S5 | 清单里的孔或空隙被填上 |

一张图只要有一条，人工严重缺陷就是真。严重缺陷率是「至少一条」的图数除以已评图数。

自动旗标只用 S1、S2、S3、S5，定义见 [METRICS.md](METRICS.md)。自动旗标可以提示去看，不能写入 `severe_defect_human`。S4 只由人判。

## 精修时间

核心商业记录是：从转换结果修到可交付，要多少分钟。空表是 [templates/retouch-log.json](templates/retouch-log.json)。

可交付指下面四条都通过，由填写人勾选，不由脚本打分：

- 剪影还能认出是原来的那个对象
- 该固件清单上的特征都在
- 没有未处理的严重缺陷
- 不透明色数仍不超过 16

计时从打开转换工程开始，到四条都勾上结束。工具可以是 `pixelforge` CLI，也可以是别的索引编辑器，但要写进 `tool`。中断、找参考的时间是否计入，由填写人在 `notes` 里写明，同一批日志用同一规则。

v1 没有精修日志。`retouch_minutes` 保持 `null`。不要用生成这张表的机器时间冒充精修时间。

## 延迟与成本

延迟是一次 `pixelforge convert` 进程的墙钟毫秒，含进程启动。每个格子跑 3 次，记录最小、中位、最大。中位取排序后的中间项；偶数个取靠后的那个中间项。这是这一台机器上的观测范围，不是标定过的性能承诺。

v1 是本机 CLI，没有按次计费。`cost_usd` 保持 `null`，状态是 `not_applicable_local_cli`。外部服务以后再记单价、币种和不确定范围，不要把 0 填成「已经测过且免费」。

## 确定性

同一张 PNG、同一个引擎、同一个策略、同一组参数，三次转换的索引和调色板必须一致。记录用这些字节的 SHA-256，不把工程 JSON 提交进 Git。工程落在 `eval/runs/pixel-convert-v1/projects/`。

## 不在本轮做的事

- 不下载或生成 100–200 张角色图。扩容规则在 [DATASET.md](DATASET.md)。
- 不接入外部服务，不训练模型。
- 不算 LPIPS。字段留空，状态 `not_computed`。
- 不把 PSNR、SSIM 或自动探针写成交付结论。
